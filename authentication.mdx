A API usa um **Bearer Token** por conta. O mesmo token vale para todos os planos e para
todos os workspaces a que a conta tem acesso.

## Obtenha o token

Há duas formas, e as duas devolvem o mesmo token:

- **Pelo dashboard**: em [app.realoficial.com.br](https://app.realoficial.com.br), abra
  **Configurações > Segurança** e copie o token.
- **Pela API**: envie email e senha para [`POST /login`](/api-reference/auth/login) e leia
  `user.token` na resposta.

O token não expira. Guarde uma vez e reutilize; não é preciso fazer login a cada
requisição.

## Envie o token

Inclua estes headers em toda requisição autenticada:

```bash
Authorization: Bearer SEU_TOKEN_AQUI
Accept: application/json
```

<Warning>
`Accept: application/json` é obrigatório na prática. Sem ele, um erro de validação volta
como redirect `302` em vez de JSON. Veja [Erros](/errors).
</Warning>

<CodeGroup>
```bash cURL
curl "https://api.realoficial.com.br/api/v1/user" \
  -H "Authorization: Bearer seu_token_aqui" \
  -H "Accept: application/json"
```

```javascript JavaScript
const response = await fetch('https://api.realoficial.com.br/api/v1/user', {
  headers: {
    Authorization: 'Bearer seu_token_aqui',
    Accept: 'application/json',
  },
});

const data = await response.json();
```

```python Python
import requests

response = requests.get(
    'https://api.realoficial.com.br/api/v1/user',
    headers={
        'Authorization': 'Bearer seu_token_aqui',
        'Accept': 'application/json',
    },
)

data = response.json()
```

```php PHP
$ch = curl_init();

curl_setopt_array($ch, [
    CURLOPT_URL => 'https://api.realoficial.com.br/api/v1/user',
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_HTTPHEADER => [
        'Authorization: Bearer seu_token_aqui',
        'Accept: application/json',
    ],
]);

$data = json_decode(curl_exec($ch), true);
```
</CodeGroup>

Uma resposta `200` com os dados da conta confirma que o token está correto. Veja os
campos em [Detalhes do Usuário](/api-reference/auth/user).

## Workspaces de equipe

Sem nenhum header extra, a requisição opera no espaço pessoal da conta. Para operar em um
workspace de equipe, envie também `X-Workspace-Id`. Veja
[Workspaces](/api-reference/workspaces).

## Proteja o token

Como o token não expira, quem tiver acesso a ele tem acesso à conta.

- Guarde o token em variável de ambiente ou em um cofre de segredos, nunca no código.
- Não envie o token para o navegador nem para apps de cliente. Faça as chamadas pelo seu
  servidor.
- Não registre o header `Authorization` em logs.

## Quando a autenticação falha

| Status | Causa |
|---|---|
| `401` | Token ausente ou inválido |
| `403` | Token válido, mas a operação exige um plano ou um papel no workspace que a conta não tem |

```json 401
{
  "error": "Token invalido ou expirado"
}
```

Os demais formatos de erro estão em [Erros](/errors).

Brand Kits armazenam logos, marcas d'água e estilos de legenda no workspace.

## Endpoints

| Método | Endpoint | Descrição |
|---|---|---|
| `GET` | `/brand-kits` | Lista Brand Kits |
| `POST` | `/brand-kits` | Cria Brand Kit |
| `GET` | `/brand-kits/{id}` | Detalha Brand Kit |
| `PUT` | `/brand-kits/{id}` | Atualiza Brand Kit |
| `POST` | `/brand-kits/{id}/duplicate` | Duplica Brand Kit |
| `DELETE` | `/brand-kits/{id}` | Remove Brand Kit |

Criação e duplicação exigem assinatura ativa. Operações de escrita exigem permissão para
gerenciar projetos no workspace.

## Criar

<ParamField body="name" type="string" required>
  Nome com até 255 caracteres.
</ParamField>

<ParamField body="format" type="string" required>
  `vertical` ou `horizontal`.
</ParamField>

<ParamField body="data" type="object" required>
  Conteúdo do Brand Kit. Aceita `version`, `logos`, `watermarks` e `caption`.
</ParamField>

Cada item de `logos` e `watermarks` aceita:

- `id`;
- `url` obrigatória;
- `fileKey`;
- `position`;
- `size`;
- `opacity` entre 0 e 1.

O objeto `caption` aceita `position`, `size` e `styles`.

<RequestExample>
```bash cURL
curl -X POST "https://api.realoficial.com.br/api/v1/brand-kits" \
  -H "Authorization: Bearer seu_token_aqui" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "name": "Campanha XPTO",
    "format": "vertical",
    "data": {
      "version": "2.0",
      "logos": [
        {
          "id": "logo-principal",
          "url": "https://cdn.exemplo.com/logo.png",
          "position": {"top": 60, "left": 60},
          "size": {"width": 200, "height": 200},
          "opacity": 1
        }
      ],
      "watermarks": [],
      "caption": {
        "position": {"top": 1200, "left": 90},
        "size": {"width": 900, "height": 400},
        "styles": {"fontFamily": "Montserrat", "color": "white"}
      }
    }
  }'
```
</RequestExample>

<ResponseExample>
```json 201 - Criado
{
  "success": true,
  "data": {
    "id": "01kbrandkit000000000000001",
    "name": "Campanha XPTO",
    "format": "vertical",
    "data": {}
  },
  "message": "Brand Kit criado com sucesso."
}
```
</ResponseExample>

## Atualizar e duplicar

`PUT /brand-kits/{id}` aceita `name`, `format` e `data`. Todos são opcionais, mas um
campo enviado precisa respeitar o mesmo schema da criação.

`POST /brand-kits/{id}/duplicate` não exige body. A cópia recebe o sufixo `(cópia)`.

## Aplicação em shorts

<Warning>
O contrato atual não possui endpoint para vincular um `brand_kit_id` a um projeto, short
ou render. Enviar `brand_kit_id` em `/createShorts` ou `/render` não aplica o kit.
</Warning>

Para automação avançada, leia `data` do Brand Kit, altere a timeline completa do short e
salve com [Atualizar Timeline](/api-reference/shorts/timeline). Essa operação é de baixo
nível: a integração é responsável por criar os assets, items e tracks correspondentes.

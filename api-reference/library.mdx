---
title: 'Biblioteca'
description: 'Organize arquivos e prompts em pastas privadas ou públicas'
---

A Biblioteca armazena metadados de arquivos e prompts no workspace ativo. Operações de
escrita exigem assinatura ativa e permissão para gerenciar projetos.

## Endpoints do workspace

| Método | Endpoint | Descrição |
|---|---|---|
| `GET` | `/library/folders` | Lista pastas |
| `POST` | `/library/folders` | Cria pasta |
| `GET` | `/library/folders/{id}` | Detalha pasta |
| `PUT` | `/library/folders/{id}` | Atualiza pasta |
| `DELETE` | `/library/folders/{id}` | Remove pasta |
| `GET` | `/library/folders/{id}/items` | Lista itens da pasta |
| `GET` | `/library/items` | Lista itens do workspace |
| `POST` | `/library/items` | Cria item |
| `GET` | `/library/items/{id}` | Detalha item |
| `PUT` | `/library/items/{id}` | Atualiza ou move item |
| `DELETE` | `/library/items/{id}` | Remove item |

## Pastas

Pastas aceitam `name` e `visibility`, que pode ser `private` ou `public`. O padrão é
`private`.

```bash
curl -X POST "https://api.realoficial.com.br/api/v1/library/folders" \
  -H "Authorization: Bearer seu_token_aqui" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{"name":"Prompts de campanha","visibility":"private"}'
```

Ao excluir uma pasta, seus itens não são excluídos: eles são movidos para a raiz da
Biblioteca (`folder_id: null`).

## Itens

Os tipos aceitos são `file` e `prompt`.

Campos comuns:

| Campo | Tipo | Regra |
|---|---|---|
| `folder_id` | string ou null | Pasta do mesmo workspace |
| `type` | string | `file` ou `prompt` |
| `name` | string | Obrigatório, máximo 255 caracteres |
| `description` | string | Opcional, máximo 5000 caracteres |
| `visibility` | string | `private` ou `public`; padrão `private` |
| `data` | object | Dados específicos do tipo |

### Item do tipo prompt

`data.content` é obrigatório. `data.tags` é opcional.

```bash
curl -X POST "https://api.realoficial.com.br/api/v1/library/items" \
  -H "Authorization: Bearer seu_token_aqui" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "folder_id": "FOLDER_ID",
    "type": "prompt",
    "name": "Cortes sobre saúde",
    "data": {
      "content": "Priorize falas completas sobre saúde pública.",
      "tags": ["saúde", "campanha"]
    }
  }'
```

### Item do tipo file

O objeto `data` exige `filename`, `mime_type` e `size`. Também aceita
`storage_provider` e `url`; quando o provider for omitido, o backend grava `r2`.

<Warning>
`POST /library/items` registra os metadados do arquivo, mas não recebe upload binário.
Informe uma URL de arquivo que já tenha sido enviado pelo fluxo de upload da aplicação.
Existe um limite de 100 novos itens `file` por dia e por workspace.
</Warning>

## Filtros

`GET /library/items` aceita `folder_id` e `type`. Para listar itens na raiz, envie
`folder_id=null` ou `folder_id=`.

`GET /library/folders/{id}/items` aceita o filtro opcional `type`.

## Catálogo público

| Método | Endpoint | Descrição |
|---|---|---|
| `GET` | `/library/public/folders` | Pastas públicas aprovadas |
| `GET` | `/library/public/folders/{id}/items` | Itens públicos de uma pasta |
| `GET` | `/library/public/items` | Itens públicos aprovados |

Esses endpoints continuam exigindo Bearer token. `public` significa visível a outros
usuários autenticados. Apenas registros com `visibility: public` e `is_approved: true`
entram no catálogo.

As listagens públicas aceitam `limit` (padrão 30, máximo 100), `page`, `type` e, na
listagem geral de itens, `folder_id`.

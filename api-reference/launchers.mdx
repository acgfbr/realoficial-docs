---
title: 'Launchers'
description: 'Fila automática de publicação com contas, horários e shorts ordenados'
---

Launchers funcionam como uma fila recorrente: você define contas e horários semanais,
adiciona shorts e o backend calcula os próximos agendamentos.

<Note>
Criação e uso de Launcher exigem assinatura ativa dos planos Criador ou Viral e permissão
de publicação no workspace.
</Note>

## Endpoints

| Método | Endpoint | Descrição |
|---|---|---|
| `GET` | `/launchers` | Lista launchers |
| `POST` | `/launchers` | Cria launcher |
| `GET` | `/launchers/{id}` | Detalha launcher, fila e histórico recente |
| `PUT` | `/launchers/{id}` | Atualiza configuração ou pausa/retoma |
| `DELETE` | `/launchers/{id}` | Remove launcher |
| `PUT` | `/launchers/{id}/slots` | Substitui todos os horários |
| `GET` | `/launchers/{id}/slots/suggest` | Sugere horários por plataforma |
| `POST` | `/launchers/{id}/suggest-description` | Sugere descrição para um short |
| `POST` | `/launchers/{id}/items` | Adiciona short a fila |
| `PUT` | `/launchers/{id}/items/reorder` | Reordena a fila |
| `PUT` | `/launchers/{id}/items/reschedule` | Desloca itens por N dias |
| `DELETE` | `/launchers/{launcherId}/items/{itemId}` | Remove item |

## Criar Launcher

<ParamField body="name" type="string" required>
  Nome, com até 255 caracteres.
</ParamField>

<ParamField body="timezone" type="string">
  Fuso dos slots. Padrão: `America/Sao_Paulo`.
</ParamField>

<ParamField body="social_account_ids" type="array" required>
  IDs de contas sociais do workspace. Exige ao menos uma conta.
</ParamField>

<ParamField body="slots" type="array">
  Horários semanais. `day_of_week` vai de 0 (domingo) a 6 (sábado) e `time_of_day`
  usa `HH:mm`.
</ParamField>

<ParamField body="default_caption_template" type="object">
  Configuração padrão de legenda aplicada pelo Launcher.
</ParamField>

<ParamField body="default_tags" type="array">
  Tags padrão.
</ParamField>

<RequestExample>
```bash cURL
curl -X POST "https://api.realoficial.com.br/api/v1/launchers" \
  -H "Authorization: Bearer seu_token_aqui" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "name": "Publicação diária",
    "timezone": "America/Sao_Paulo",
    "social_account_ids": ["01ksocialaccount000000000001"],
    "slots": [
      {"day_of_week": 1, "time_of_day": "18:00"},
      {"day_of_week": 3, "time_of_day": "18:00"},
      {"day_of_week": 5, "time_of_day": "18:00"}
    ]
  }'
```
</RequestExample>

O Launcher é criado com status `active`. `PUT /launchers/{id}` aceita `active` ou
`paused`, além dos campos de configuração.

## Atualizar slots

`PUT /launchers/{id}/slots` recebe `{ "slots": [...] }` e substitui atomicamente todos os
horários. A fila pendente é recalculada depois da troca.

As sugestões de `GET /launchers/{id}/slots/suggest` usam benchmarks genéricos por
plataforma. Elas não são uma previsão baseada no histórico individual da conta.

## Adicionar um short

<ParamField body="short_id" type="string" required>
  Short do workspace com timeline renderizável.
</ParamField>

<ParamField body="description" type="string">
  Descrição padrão, com até 5000 caracteres.
</ParamField>

<ParamField body="caption_overrides" type="object">
  Sobrescritas de legenda por plataforma/conta.
</ParamField>

<ParamField body="tiktok_guidelines_filter_enabled" type="boolean">
  Padrão: `true`.
</ParamField>

<ParamField body="auto_reply_config" type="object">
  Mesma configuração opcional aceita pela API de publicações.
</ParamField>

```bash
curl -X POST "https://api.realoficial.com.br/api/v1/launchers/LAUNCHER_ID/items" \
  -H "Authorization: Bearer seu_token_aqui" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "short_id": "01k4ef56yqtsyrzjb0gveqy7cd",
    "description": "Confira este corte"
  }'
```

O mesmo short não pode aparecer duas vezes na fila pendente do Launcher.

## Reordenar e reagendar

Para reordenar, envie todos os IDs na ordem desejada:

```json
{ "item_ids": ["ITEM_3", "ITEM_1", "ITEM_2"] }
```

Para deslocar itens por dias, use `items/reschedule`:

```json
{
  "item_ids": ["ITEM_1", "ITEM_2"],
  "days": 7
}
```

`days` aceita valores entre -365 e 365, exceto zero. Um deslocamento que coloque a
publicação no passado retorna `422` com o código `scheduled_in_past`.

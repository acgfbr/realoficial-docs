## Endpoint

```
POST https://api.realoficial.com.br/api/v1/profile
```

<Note>
Este endpoint requer autenticacao via Bearer Token.
</Note>

<Warning>
Este endpoint aceita apenas `POST`. Uma requisicao `GET` retorna `405 Method Not Allowed`
— para **ler** os dados do perfil, use [Dados do Usuario](/api-reference/auth/user).
</Warning>

Todos os campos sao opcionais: envie apenas os que quiser alterar. Campos ausentes do body
permanecem inalterados.

## Body Parameters

<ParamField body="name" type="string">
  Nome do usuario. Maximo 255 caracteres.
</ParamField>

<ParamField body="nickname" type="string">
  Apelido/nome de exibicao. Maximo 255 caracteres.
</ParamField>

<ParamField body="email" type="string">
  Email do usuario. Precisa ser unico e ter formato valido. Maximo 255 caracteres.
</ParamField>

<ParamField body="phone" type="string">
  Telefone. Maximo 20 caracteres.
</ParamField>

<ParamField body="tax_id" type="string">
  CPF ou CNPJ. Maximo 20 caracteres.
</ParamField>

<ParamField body="pix_key" type="string">
  Chave PIX usada para recebimentos. Maximo 255 caracteres.
</ParamField>

<ParamField body="ignore_notifications" type="boolean">
  Desliga o envio de notificacoes por email.
</ParamField>

<ParamField body="webhook_url" type="string">
  URL que recebera os eventos de webhook. Envie `null` ou string vazia para desativar.

  Veja [Webhooks](#webhooks) abaixo para as restricoes de URL.
</ParamField>

<Note>
Campos nao listados aqui — como `balance`, `token`, `read_only_token` ou os campos de cota
— **nao sao editaveis** por este endpoint, mesmo aparecendo no `GET /user`. Enviar esses
campos nao produz erro; eles simplesmente sao ignorados.
</Note>

## Webhooks

Ao definir `webhook_url`, a Real Oficial passa a enviar `POST` com JSON para essa URL
quando um projeto fica pronto (`project.ready`) ou uma renderizacao termina
(`render.completed`).

A URL passa por validacao de seguranca e precisa:

- usar esquema `http` ou `https`;
- apontar para um host publico resolvivel.

URLs apontando para enderecos internos/privados sao rejeitadas com `422`.

<Warning>
Trate a URL de webhook como um **segredo**. Ela e o unico fator que autentica as
notificacoes recebidas — quem souber a URL consegue enviar payloads forjados para o seu
endpoint. Prefira uma URL longa e com componente aleatorio, e valide o conteudo recebido
antes de agir sobre ele.
</Warning>

## Resposta de Sucesso

<ResponseField name="message" type="string">
  Mensagem de confirmacao
</ResponseField>

<ResponseField name="user" type="object">
  O objeto do usuario ja com os dados atualizados.
</ResponseField>

<RequestExample>
```bash cURL
curl -X POST "https://api.realoficial.com.br/api/v1/profile" \
  -H "Authorization: Bearer seu_token_aqui" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "webhook_url": "https://meu-app.com/webhooks/realoficial/SEGREDO"
  }'
```

```javascript JavaScript
const response = await fetch('https://api.realoficial.com.br/api/v1/profile', {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer seu_token_aqui',
    'Content-Type': 'application/json',
    'Accept': 'application/json'
  },
  body: JSON.stringify({
    webhook_url: 'https://meu-app.com/webhooks/realoficial/SEGREDO'
  })
});

const { user } = await response.json();
```

```python Python
import requests

response = requests.post(
    'https://api.realoficial.com.br/api/v1/profile',
    headers={
        'Authorization': 'Bearer seu_token_aqui',
        'Content-Type': 'application/json',
        'Accept': 'application/json'
    },
    json={'webhook_url': 'https://meu-app.com/webhooks/realoficial/SEGREDO'}
)

data = response.json()
```
</RequestExample>

</ResponseExample>

## Desativando o webhook

Envie `null` (ou string vazia) para parar de receber notificacoes:

```bash
curl -X POST "https://api.realoficial.com.br/api/v1/profile" \
  -H "Authorization: Bearer seu_token_aqui" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{ "webhook_url": null }'
```

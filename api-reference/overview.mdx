## URL base

```
https://api.realoficial.com.br/api/v1
```

Todos os caminhos desta documentação são relativos a essa URL.

## Headers

| Header | Valor | Quando enviar |
|---|---|---|
| `Authorization` | `Bearer {token}` | Sempre, exceto em `POST /login` e nos endpoints públicos de preço |
| `Accept` | `application/json` | Sempre |
| `Content-Type` | `application/json` | Em requisições com corpo |
| `X-Workspace-Id` | ULID do workspace | Só para operar em um workspace de equipe |

Sem `Accept: application/json`, erros de validação voltam como redirect `302` em vez de
JSON. Veja [Erros](/errors).

## Workspace da requisição

Toda requisição autenticada opera em exatamente um workspace:

- sem `X-Workspace-Id`, ou com o header vazio, usa o espaço pessoal;
- com `X-Workspace-Id: {ulid}`, usa o workspace de equipe indicado;
- o usuário precisa ser o dono ou um membro ativo desse workspace;
- recursos de outro workspace não são procurados automaticamente e respondem `404`.

```bash
curl "https://api.realoficial.com.br/api/v1/projects" \
  -H "Authorization: Bearer seu_token_aqui" \
  -H "X-Workspace-Id: 01KZWORKSPACE000000000001" \
  -H "Accept: application/json"
```

`GET /workspaces` lista os espaços acessíveis. Papéis, saldo e isolamento estão em
[Workspaces](/api-reference/workspaces).

## IDs

Projetos, shorts, renders e a maioria dos recursos usam ULID: 26 caracteres, como
`01k3ab12yqtsyrzjb0fveqy5zx`. Trate IDs como texto.

## Operações assíncronas

Processar um vídeo, renderizar e gerar com IA não terminam na mesma requisição. O
endpoint devolve o recurso com um status inicial e o resultado aparece depois.

- **Polling**: consulte o endpoint de status indicado na página de cada recurso.
- **Webhook**: para projetos e renders, configure uma URL em
  [Atualizar Perfil](/api-reference/auth/profile#webhooks) e receba `project.ready` e
  `render.completed`. Os recursos de IA não têm webhook.

## Respostas

Os endpoints da v1 não compartilham um envelope único. Alguns devolvem `message` e
`data`, outros devolvem o recurso direto. Siga o exemplo de resposta da página de cada
endpoint em vez de presumir um formato.

Os formatos de erro e os status HTTP estão em [Erros](/errors).

## Paginação

Listas são paginadas com `page` e com `limit` ou `per_page`, conforme o endpoint. O
tamanho padrão e o máximo também variam; confira a página do endpoint.

Existem dois formatos de resposta paginada:

<CodeGroup>
```json Paginador dentro de data
{
  "message": "Lista de shorts obtida com sucesso.",
  "data": {
    "current_page": 1,
    "data": [],
    "last_page": 3,
    "per_page": 10,
    "total": 24
  }
}
```

```json links e meta
{
  "data": [],
  "links": {
    "first": "https://api.realoficial.com.br/api/v1/projects?page=1",
    "last": "https://api.realoficial.com.br/api/v1/projects?page=10",
    "prev": null,
    "next": "https://api.realoficial.com.br/api/v1/projects?page=2"
  },
  "meta": {
    "current_page": 1,
    "last_page": 10,
    "per_page": 20,
    "total": 200
  }
}
```
</CodeGroup>

No primeiro formato, os itens ficam em `data.data`. É o caso de
[Listar Shorts](/api-reference/shorts/list) e [Listar Renders](/api-reference/renders/list).
No segundo, ficam em `data`, como em [Listar Projetos](/api-reference/projects/list).

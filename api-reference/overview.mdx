## Base URL

Todas as requisicoes devem ser feitas para:

```
https://api.realoficial.com.br/api/v1
```

## Headers Padrao

Todas as requisicoes devem incluir os seguintes headers:

| Header | Valor | Obrigatorio |
|--------|-------|-------------|
| `Authorization` | `Bearer {token}` | Sim (exceto login) |
| `Content-Type` | `application/json` | Sim para POST/PUT |
| `Accept` | `application/json` | Sim |
| `X-Workspace-Id` | ULID do workspace | Somente para operar em um workspace de equipe |

## Contexto de Workspace

Toda requisicao autenticada opera em exatamente um workspace:

- sem `X-Workspace-Id`, ou com o header vazio, usa o espaco pessoal;
- com `X-Workspace-Id: {ulid}`, usa o workspace de equipe indicado;
- o usuario autenticado precisa ser o dono ou um membro ativo desse workspace;
- recursos de outro workspace nao sao procurados automaticamente.

```bash
curl "https://api.realoficial.com.br/api/v1/projects" \
  -H "Authorization: Bearer seu_token_aqui" \
  -H "X-Workspace-Id: 01KZWORKSPACE000000000001" \
  -H "Accept: application/json"
```

Use `GET /workspaces` para listar os espacos acessiveis e obter o ID correto. Consulte
[Workspaces](/api-reference/workspaces) para isolamento de recursos, papeis, saldo e
endpoints de gestao.

## Formato de Resposta

Envie `Accept: application/json` em todas as requisicoes. Sem esse header, erros de
validacao ou autenticacao podem seguir o comportamento padrao do Laravel e retornar um
redirect HTTP em vez do JSON esperado.

Os endpoints historicos da API possuem envelopes diferentes. Use o contrato descrito na
pagina de cada endpoint; nao presuma que toda resposta usa obrigatoriamente `message` e
`data`.

### Resposta de Sucesso

```json
{
  "message": "Operacao realizada com sucesso",
  "data": { ... }
}
```

### Resposta de Erro

```json
{
  "error": "Descricao do erro"
}
```

## Codigos HTTP

| Codigo | Descricao |
|--------|-----------|
| `200` | Sucesso |
| `201` | Criado com sucesso |
| `202` | Aceito (processamento assincrono) |
| `208` | Recurso ja existente e reutilizado |
| `400` | Requisicao invalida |
| `401` | Nao autenticado |
| `403` | Sem permissao |
| `404` | Nao encontrado |
| `422` | Erro de validacao ou regra de negocio |
| `429` | Muitas requisicoes (rate limit) |
| `500` | Erro interno do servidor |

## Paginacao

Endpoints que retornam listas podem utilizar paginacao. Os nomes dos campos, o limite
maximo e o valor padrao variam por recurso; confira a pagina do endpoint.

```json
{
  "data": [...],
  "links": {
    "first": "https://api.realoficial.com.br/api/v1/projects?page=1",
    "last": "https://api.realoficial.com.br/api/v1/projects?page=10",
    "prev": null,
    "next": "https://api.realoficial.com.br/api/v1/projects?page=2"
  },
  "meta": {
    "current_page": 1,
    "from": 1,
    "last_page": 10,
    "per_page": 20,
    "to": 20,
    "total": 200
  }
}
```

### Parametros de Paginacao

| Parametro | Tipo | Descricao | Padrao |
|-----------|------|-----------|--------|
| `page` | integer | Numero da pagina | 1 |
| `per_page` ou `limit` | integer | Itens por pagina; limite depende do endpoint | Consulte o endpoint |

## Base URL

Todas as requisições devem ser feitas para:

```
https://api.realoficial.com.br/api/v1
```

## Headers Padrão

Todas as requisições devem incluir os seguintes headers:

| Header | Valor | Obrigatório |
|--------|-------|-------------|
| `Authorization` | `Bearer {token}` | Sim (exceto login) |
| `Content-Type` | `application/json` | Sim para POST/PUT |
| `Accept` | `application/json` | Sim |
| `X-Workspace-Id` | ULID do workspace | Somente para operar em um workspace de equipe |

## Contexto de Workspace

Toda requisição autenticada opera em exatamente um workspace:

- sem `X-Workspace-Id`, ou com o header vazio, usa o espaço pessoal;
- com `X-Workspace-Id: {ulid}`, usa o workspace de equipe indicado;
- o usuário autenticado precisa ser o dono ou um membro ativo desse workspace;
- recursos de outro workspace não são procurados automaticamente.

```bash
curl "https://api.realoficial.com.br/api/v1/projects" \
  -H "Authorization: Bearer seu_token_aqui" \
  -H "X-Workspace-Id: 01KZWORKSPACE000000000001" \
  -H "Accept: application/json"
```

Use `GET /workspaces` para listar os espaços acessíveis e obter o ID correto. Consulte
[Workspaces](/api-reference/workspaces) para isolamento de recursos, papéis, saldo e
endpoints de gestão.

## Formato de Resposta

Envie `Accept: application/json` em todas as requisições. Sem esse header, erros de
validação ou autenticação podem seguir o comportamento padrão do Laravel e retornar um
redirect HTTP em vez do JSON esperado.

Os endpoints históricos da API possuem envelopes diferentes. Use o contrato descrito na
página de cada endpoint; não presuma que toda resposta usa obrigatoriamente `message` e
`data`.

### Resposta de Sucesso

```json
{
  "message": "Operação realizada com sucesso",
  "data": { ... }
}
```

### Resposta de Erro

```json
{
  "error": "Descrição do erro"
}
```

## Códigos HTTP

| Código | Descrição |
|--------|-----------|
| `200` | Sucesso |
| `201` | Criado com sucesso |
| `202` | Aceito (processamento assíncrono) |
| `208` | Recurso já existente e reutilizado |
| `400` | Requisição inválida |
| `401` | Não autenticado |
| `403` | Sem permissão |
| `404` | Não encontrado |
| `422` | Erro de validação ou regra de negócio |
| `429` | Muitas requisições (rate limit) |
| `500` | Erro interno do servidor |

## Paginação

Endpoints que retornam listas podem utilizar paginação. Os nomes dos campos, o limite
máximo e o valor padrão variam por recurso; confira a página do endpoint.

```json
{
  "data": [...],
  "links": {
    "first": "https://api.realoficial.com.br/api/v1/projects?page=1",
    "last": "https://api.realoficial.com.br/api/v1/projects?page=10",
    "prev": null,
    "next": "https://api.realoficial.com.br/api/v1/projects?page=2"
  },
  "meta": {
    "current_page": 1,
    "from": 1,
    "last_page": 10,
    "per_page": 20,
    "to": 20,
    "total": 200
  }
}
```

### Parâmetros de Paginação

| Parâmetro | Tipo | Descrição | Padrão |
|-----------|------|-----------|--------|
| `page` | integer | Número da página | 1 |
| `per_page` ou `limit` | integer | Itens por página; limite depende do endpoint | Consulte o endpoint |
